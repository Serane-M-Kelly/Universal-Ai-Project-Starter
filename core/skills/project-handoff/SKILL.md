# project-handoff

Sans `.starter/workflow.json`, suivre uniquement [la procédure historique](references/legacy-v014.md).
Avec un suivi v3, appliquer la suite ci-dessous.

Lire `.starter/WORKFLOW.md` et PROJECT_BRIEF.md. Vérifier cohérence avec les sources acceptées,
périmètre, critères testables et questions bloquantes. Conserver les références PA/AD applicables ;
une maquette n'est pas une vérification fonctionnelle. Réutiliser les décisions antérieures accessibles
qui couvrent exactement le brief. Consigner leur attribution réelle par `workflow brief-approve
--by PERSONNE --request MOTS_REELS`. Une recommandation d'agent, un import réussi ou un document
marqué prêt ne constitue pas une acceptation humaine. Soumettre seulement les écarts nouveaux.
Ne pas créer de rapport supplémentaire si aucune décision ou preuve ne le justifie. Une approbation
portant sur un périmètre différent ne se transfère pas. Poursuivre le setup déjà autorisé.

## Visibilité dans la recherche, selon le périmètre

Si la visibilité par recherche est applicable, vérifier que le brief référence les pages/contenus concernés, les critères techniques et les limites de migration ou de mesure. Distinguer résultat livrable et performance future ; ne pas imposer un nouveau dossier SEO ni un engagement de classement.
